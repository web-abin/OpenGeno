## 功能文档（OpenGeno）

本项目使用 [OpenGeno](https://github.com/web-abin/OpenGeno) 在 `feat-tree/`
下维护功能文档树。文档树是所有用户可见行为的唯一权威来源。

**文档语言：中文。** 在 `feat-tree/` 下新建或修改任何文件时，所有正文、标题、
注释、frontmatter 字段值都用中文写。不要在文档树内混用语言。

### 改之前先读文档

在修改某个已有功能的**用户可见行为**之前：

1. 读 `feat-tree/index.md`，定位相关模块。
2. 读 `feat-tree/<module>/index.md`（L2），定位具体功能。
3. 在编辑任何代码之前，先读该功能的 L3 文档
   （`feat-tree/<module>/<feature>.md`）。
4. 如果文档树里找不到这个功能但你又要改它的行为，**先停下来创建 L3 文档**
   （见下方「新增功能」）。给没文档的功能改行为会留下永久文档债。
5. 跨功能链接默认只跟**一跳**，除非有特定理由不要递归跟链。

### 改完之后更新文档

在**同一次对话内**完成代码修改后：

1. 重新读该功能的 L3 文档。
2. 逐节走查，只改有变化的小节。
3. 如果你新增 / 删除了一条出向跨功能链接，同时去链接目标的 L3 文档里
   更新它的「跨功能链路」一节，把入向引用补齐。
4. 把 `last_synced_commit:` 改为当前 `git rev-parse HEAD`，把 `last_reviewed:`
   改为今天。
5. **关键**：只有当你确实在本次对话内重读过相关代码，才能更新
   `last_synced_commit`。不验证就刷新 SHA 是这套系统唯一会被彻底毁掉的方式。
   不确定就保持旧 SHA，让 `/geno-sync` 之后再标出来。

### 哪些改动需要更新文档

| 改动 | 是否更新 |
|------|---------|
| 新增 / 删除用户可见行为 | **必须** |
| 修改交互流程、布局、动效 | **必须** |
| 修改业务逻辑分支（条件、规则） | **必须** |
| 新增 / 删除跨模块依赖 | **必须（双方都要）** |
| 修 bug，新代码符合原文档描述 | 不更新 |
| 修 bug 但行为变了（即使是修对的方向） | **必须** |
| 重构 / 改命名（行为不变） | 不更新 |
| 性能优化（行为不变） | 不更新 |
| i18n、文案、纯样式调整 | 不更新 |

判断标准：用户能不能感知到？能 → 必须更新。

### 新增功能

实现一个全新功能时：

1. 决定它属于哪个模块（已有的或新建的）。
2. 从已安装的 OpenGeno skill 模板里挑对应的：
   - UI 功能 → `templates/feature-ui.zh.md`
   - 逻辑功能 → `templates/feature-logic.zh.md`
3. 用模板创建 `feat-tree/<module>/<feature>.md`，把真实内容填进去
   （线稿、交互 / 触发条件、逻辑、状态、边界情况、跨链路）。**不要**留
   `TODO` 占位。
4. 在 `feat-tree/<module>/index.md` 的「功能」表里追加一行。
5. 如果有现有功能能进到这个新功能，去那些功能的 L3 文档里加上出向跨链接。
6. `last_synced_commit: ""` 保持空，等代码落地后按"改完后更新文档"的流程
   再补 SHA。

### 怀疑文档已漂移

如果你怀疑文档树和代码不一致（比如刚合并了分支、刚做完 vibe-coding、有
人绕过本流程改了代码），运行 `/geno-sync`。

### 哪些不在文档树范围

下列内容是基础设施而非功能，写在代码注释、ADR 或本 CLAUDE.md 里，不进
`feat-tree/`：

- 国际化 / 翻译
- 数据埋点 / 用户行为分析
- 构建工具、CI/CD
- 异常上报（Sentry 等）
- 日志
- 纯工具方法
- 主题原语（颜色、字体 token）
